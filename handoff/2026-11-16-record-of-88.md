## What the pinned CLI does, as read (1.29.0, `dist/`)

- **The update worker** (`utils/auto-update.js`). `startAutoUpdate` runs on every command
  but `update`, and not for `--status`. When an update may be due it starts the CLI again, detached,
  with the whole environment plus a worker flag: on a keyed call that copy holds the key.
  `FIRECRAWL_NO_UPDATE_CHECK` (`1` or `true`) ends `startAutoUpdate` at its first line;
  `FIRECRAWL_NO_AUTO_UPDATE` (`1` or `true`) is one of the blockers checked before the
  start, with `CI` and the user's own off switch.
- **Whether the worker ever ran here: no.** The pinned install answers
  `{"kind":"unsupported","code":"not-global"}` to the CLI's own install detection, and an
  install it does not support never updates itself. `~/.firecrawl`, where the updater keeps its
  state and the update cache, does not exist on the PC. The switches are for a later pin
  or a changed detection.
- **Why both switches.** `FIRECRAWL_NO_AUTO_UPDATE` alone stops the worker and leaves the
  update notice: on a terminal it asks the npm registry (no key is sent) and prints a
  command for an install this PC does not have. `FIRECRAWL_NO_UPDATE_CHECK` stops the
  notice, the registry call and the notice about newer skills too. Updates of the pin come
  from the Cookbook's update check.
- **Commands.** `research search-github` and `agent thread` are subcommands of commands
  that were already listed: they got the key before, and a test now says so. The other
  three the review named:
  - `credit-usage` (`credits`): one `GET /v2/team/credit-usage` with the key as a bearer
    token; `-o` writes the answer. Added.
  - `list` (`list-tools`): the Alexandria index, the same handler as `alexandria browse`,
    which was listed. Added.
  - `download` exists only as `experimental download` (`x download`). The group also holds
    `sql`, which can start paid provider calls. Left out on purpose: a group gets new
    commands between versions, and each would get the key unread. The hidden top-level
    `sql` is left out with it.
  - `browser` (hidden, deprecated for `interact`): every subcommand calls the API, and its
    code runs in Firecrawl's remote sandbox. But `commands/browser.js` exports
    `executeBashLocally`, which starts `sh -c` on this PC with the whole environment.
    Nothing calls it in 1.29.0. Left out on purpose.
  - Also named now: `logout`, `create` (a starter project) and `version`.
